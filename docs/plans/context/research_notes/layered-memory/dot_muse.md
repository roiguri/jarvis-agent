# OpenAI Dots and Meta Muse: memory and context architecture (as of 2026-10-06)

Scope note: the user clarified mid-research that "Dot" means **OpenAI's personal agent "dots"** (launched at DevDay 2026-09-29), not New Computer's Dot app, and "Muse" means **Meta's personal agent Muse** (launched 2026-09-08). Both shipped within the last month, so almost everything public is launch material: official help pages and posts, plus secondary write-ups. openai.com and help.openai.com were not fetched directly (other researchers got 403s), so every OpenAI claim below comes through secondary articles that quote OpenAI docs. **No architecture talk, engineering blog, paper or post-mortem exists yet for either product.** New Computer's Dot is kept as a short footnote at the end.

Labels: **[Official]** = Meta/OpenAI first-party text, directly fetched or quoted verbatim by a secondary source. **[3P]** = third-party analysis or hands-on testing. **[3P-quoting-official]** = a third party paraphrasing official docs I could not open myself.

## OpenAI dots: what it is, launch, availability, memory/context architecture

### Takeaway
dots are always-on ChatGPT agents, launched 2026-09-29. Each runs on GPT-6 Astra with its own cloud computer, and messages reach it from ChatGPT, Slack and Teams. Its memory has three inputs. The current conversation and tool results. Relevant ChatGPT Memory, which is shared both ways and is itself curated in the background by ChatGPT's "Dreaming" (shipped 2026-06-04). The dot's own **private notes**, which are a separate store and "not a transcript". Those notes are written partly by an idle-time "proactive research" mode that is **read-only**. The dot can schedule its own wake-ups, run on schedules, or react to events. The user cannot see or edit the notes. No dots-specific consolidation process has been published.

### Cited Findings
- **Launch / identity [3P, 2026-09-29]:** announced at OpenAI DevDay on 2026-09-29. It is a "personal agentic assistant powered by GPT-6 Astra", "meant to operate independent of any specific hardware or interface, pursuing user-defined goals continuously in the background with minimal oversight." Available in ChatGPT and Codex for Pro and Business Premium in eligible markets. — [TechCrunch](https://techcrunch.com/2026/09/29/openai-launches-dots-its-bubbly-agentic-avatar/)
- **Availability / multi-dot roadmap [3P, 2026-09-29]:** "your first Dot is free" on Pro/Business Premium. One primary Dot per user today; "teams of Dots" planned. You can message or call a dot in ChatGPT on desktop, web and mobile. — [Engadget](https://www.engadget.com/2272230/dots-are-openais-new-personal-agents-and-soon-youll-be-able-to-control-several-of-them/)
- **Channels, cloud computer, plugins [3P]:** each dot has its own cloud computer and browser and can reach 4,000+ apps through plugins. It can be messaged from Slack and Teams, with SMS "coming soon". — [AI Weekly](https://aiweekly.co/alerts/openai-launches-dots-always-on-chatgpt-agents-at-devday); [TechCrunch](https://techcrunch.com/2026/09/29/openai-launches-dots-its-bubbly-agentic-avatar/)
- **Cross-channel context [3P-quoting-official]:** "Dots can carry context across every surface you can interact with them on." — [Engadget](https://www.engadget.com/2272230/dots-are-openais-new-personal-agents-and-soon-youll-be-able-to-control-several-of-them/). Also: "a project started in ChatGPT can be picked up in a Slack thread without re-explaining anything." — [DataCamp, 2026-09-29](https://www.datacamp.com/blog/openai-dots)
- **Three context inputs [3P-quoting-official, 2026-09-30]:** a dot works from "(1) the conversation it's working in, plus source material and tool results (2) relevant ChatGPT memory (3) its own saved notes about your preferences, decisions and ongoing work". The notes are "separate from ChatGPT's saved memory and they're not a transcript." — [Flavio Copes, citing OpenAI launch post, dots docs, Help Center FAQ and GPT-6 Astra system card](https://flaviocopes.com/openai-dots/)
- **Two-way link to ChatGPT Memory [3P-quoting-official]:** "A dot receives memories and recent context from ChatGPT. Conversations with the dot can also feed back into ChatGPT Memory." The dot keeps "context from your conversations and plugins for as long as you keep the dot." — [MemU blog](https://memu.pro/blog/openai-dots)
- **Memories formed without being asked [3P-quoting-official]:** "Your dot inherits memories from ChatGPT and creates its own, including memories formed from connected apps when you haven't asked a specific question about them." — [DataCamp](https://www.datacamp.com/blog/openai-dots)
- **What is excluded from context [3P-quoting-official]:** the context "doesn't keep credentials, images or screenshots". On voice calls the dot "uses a selection of the conversation context, which can differ from what a background task sees". So foreground calls and background tasks assemble context differently. — [Flavio Copes](https://flaviocopes.com/openai-dots/)
- **Proactive research (background writer) [3P-quoting-official]:** when you are not working with it, the dot "reads information from the apps it has permission to read, keeps private notes about what it finds, and brings you a suggestion or a question." — [Flavio Copes](https://flaviocopes.com/openai-dots/). In that mode its tools are "restricted to read-only… it cannot send messages, change app content, or control your browser or computer." — [DataCamp](https://www.datacamp.com/blog/openai-dots). Any action taken afterwards on what it found goes through the normal safety checks. Custom Rules can loosen or tighten those actions but cannot lift the proactive-research restrictions. — [Search Engine Journal, 2026-09-30](https://www.searchenginejournal.com/openai-dots-read-only-proactive-research/591565/). The official FAQ page is [help.openai.com/articles/20001529](https://help.openai.com/articles/20001529) (not fetched).
- **Wake-up mechanics [3P-quoting-official]:** the dot is activated in three ways. (1) It "can decide when to pause and wake up to continue work". (2) Fixed schedules set by the user, with a timezone and notification preferences. (3) Event-driven: "When a connected service supports it, your dot can react to something happening." — [Flavio Copes](https://flaviocopes.com/openai-dots/). Example given: "a morning review of your calendar". — [DataCamp](https://www.datacamp.com/blog/openai-dots)
- **Memory opacity and deletion [3P-quoting-official]:** "You can't view, correct or delete individual dot memories. Deleting the dot is the only way to clear them." — [Flavio Copes](https://flaviocopes.com/openai-dots/). "Disconnecting an app does not remove what your dot already learned from it." — [DataCamp](https://www.datacamp.com/blog/openai-dots). A full reset deletes conversations, saved memories and scheduled tasks. — [SEJ](https://www.searchenginejournal.com/openai-dots-read-only-proactive-research/591565/). One outlet's headline frames this as "memories you cannot read". — [University 365](https://www.university-365.com/post/openai-dots-always-on-agents-with-their-own-cloud-computer-and-memories-you-cannot-read)
- **Training [3P-quoting-official]:** OpenAI does not train directly on proactive research or the dot's private notes. — summarized in search results from [SEJ](https://www.searchenginejournal.com/openai-dots-read-only-proactive-research/591565/) / [help.openai.com FAQ](https://help.openai.com/articles/20001529) (FAQ not fetched).
- **Cost model [3P-quoting-official]:** conversations do not use up limits. Deeper work "draws on a plan allowance", with extended limits in the first month, and "terms after that are not published". — [DataCamp](https://www.datacamp.com/blog/openai-dots); [Flavio Copes](https://flaviocopes.com/openai-dots/)
- **CEO anecdotes [Official-ish: Sam Altman on a podcast, 2026-09-30]:** Altman calls his dot "Dotty". He says it pulls together Slack, email, calendar and screenshots. It "kept thinking about it overnight" and found a forgotten screenshot. It flagged a production issue to an engineer five minutes before his DevDay demo. He describes the value as "the ability to bring context together from across your entire life." — [Every podcast transcript](https://every.to/podcast/transcript-how-sam-altman-uses-dots-to-take-back-his-time)
- **Tester anecdote [3P-quoting-official]:** "a tester's Dot noticed they had forgotten to bill a publication for an article. The Dot prepared an invoice and sent it on the person's behalf." — [Engadget](https://www.engadget.com/2272230/dots-are-openais-new-personal-agents-and-soon-youll-be-able-to-control-several-of-them/)
- **ChatGPT "Dreaming" (the upstream memory dots inherit) [3P, reported 2026-06]:** rolled out 2026-06-04. It is "a method for ChatGPT to automatically curate memories in the background by referencing chat history". It targets staleness, correctness and scale. Factual recall on OpenAI's own eval reportedly went from 41.5% to 82.8%. — [ResultSense, 2026-06-05](https://www.resultsense.com/news/2026-06-05-openai-chatgpt-dreaming-memory/); [Mem0 article on X](https://x.com/mem0ai/article/2071990201531118063); [Digital Applied](https://www.digitalapplied.com/blog/chatgpt-memory-dreaming-v3-openai-2026-guide). (Search-snippet level only; I did not fetch these in full. A separate researcher may cover Dreaming in depth.)
- **No consolidation described for dots [3P]:** "No consolidation or 'Dreaming' mechanism is described" for the dot's own notes. "We found no independent test of how well a dot performs on real work." — [MemU blog](https://memu.pro/blog/openai-dots)

### Inferences
- The layering looks like this. A **shared, background-curated profile** (ChatGPT Memory, consolidated by Dreaming) is pulled in selectively ("relevant ChatGPT memory"), so it is probably retrieved rather than fully injected. On top of it sits an **agent-private notes store** written both during conversations and by idle-time read-only research. This is close to Jarvis's split: USER.md as the durable profile, per-task heartbeat notes as agent narrative state, and the heartbeat as idle-time work.
- Making proactive mode read-only is the safety design worth copying. Background ticks may observe and write notes, but anything with side effects goes through the foreground or approval path. That is roughly Jarvis's heartbeat → notify pattern, made into an explicit rule.
- "Not a transcript" signals that the notes store is distilled and agent-written (decisions, preferences, ongoing work), not a raw log. Jarvis's daily logs plus curated memory files already match that.
- The user-trust weak spot is clear: invisible, non-editable memory, and learning that survives disconnecting an app. Jarvis's human-readable markdown memory is a real advantage over dots here.
- Context assembly varies by entry point (a call versus a background task sees different selections). That supports Jarvis's per-scope `build_system_prompt` design.

### Gaps
- Could not fetch openai.com or help.openai.com (403 reported). All official dots text is second-hand quotation. The GPT-6 Astra system card's memory sections were not reviewed directly.
- Unknown: the storage format of dot notes, whether retrieval is semantic search, any size limits or compaction, how relevant ChatGPT memories are chosen, how often proactive research runs, and the logic that decides when to notify.
- No engineering post, talk, eval or reverse-engineering of dot internals was found. Less than a week of public use means no lessons learned or post-mortem yet.

## Meta Muse: what it is, launch, availability, memory/context architecture

### Takeaway
Meta Muse, launched 2026-09-08, is a proactive personal agent on the Muse Spark model. It runs in a per-user cloud VM ("Muse Secure VM") and is reached through its own app, the web, and WhatsApp. Its memory is **file-based and visible to the user**. A curated **MEMORY.md** (durable facts, preferences, commitments) sits next to **dated notes** in a memory directory, with semantic search across both. That is structurally almost the same as OpenClaw and Jarvis. Meta officially documents a "forget" skill, editable memory files, a Goals tab, compaction of long chats, and a reset. Meta also states plainly that deleted material may persist in what Muse learned.

### Cited Findings
- **Launch / identity [3P reporting official, 2026-09-08/09]:** announced 2026-09-08. It is a messaging-style personal agent that works on its own cloud computer and keeps working after the app is closed. Initial rollout is the US on iOS, Android and the web, free with paid tiers. — [The National, 2026-09-08](https://www.thenationalnews.com/future/technology/2026/09/08/meta-muse-ai-agent/); [ADN/AP, 2026-09-08](https://www.adn.com/business-economy/2026/09/08/meta-debuts-muse-its-long-planned-personal-ai-agent/); [The Star, 2026-09-09](https://www.thestar.com.my/tech/tech-news/2026/09/09/meta-launches-personal-ai-agent-muse-emphasises-safety-and-privacy)
- **Model, channels, memory claim [3P-quoting-official]:** runs on "Muse Spark". It is reachable through the app or WhatsApp. It "can remember what matters to a user, make suggestions without being prompted and act on details shared previously, including information mentioned only once." "Users can also tell Muse to forget specific information it has learned." — [FoneArena](https://www.fonearena.com/blog/491913/meta-muse-personal-ai-agent-features.html)
- **Runtime isolation [3P-quoting-official]:** "Muse Secure VM, a dedicated virtual machine that houses the agent and the user's data". A separate "Sentinel agent runs on the same machine and stays isolated from Muse at the system level". "Muse Confidential VM", planned for later in 2026, will encrypt the whole VM with a user-held key. Muse returns "when something changes or when it needs user approval, such as before sending an email or making a purchase." — [FoneArena](https://www.fonearena.com/blog/491913/meta-muse-personal-ai-agent-features.html)
- **MEMORY.md, forget, reset [Official, Meta Help Center, fetched 2026-10-06]:** "You can find out what Muse remembers about you at any time by asking directly, or by viewing files like your MEMORY.md." Data lives in the VM, and Meta "maintains backups to help protect your agent's history from data loss." For the forget skill, you "simply ask Muse to forget a topic or set of interactions". It works by asking "Muse to look for information about a specific person, topic or matter in its memories and supporting files and remove it to the best of its ability." "Reset Muse… deletes all your Muse data." Caveat: "Muse may still remember information it learned from what you deleted." — [Meta Help: How Muse handles your privacy, safety and security](https://www.meta.com/help/artificial-intelligence/1047255454427887/)
- **Four memory sources [3P-quoting-official]:** Muse "builds its understanding of you from four sources": conversations, observed preferences and patterns, context from connected services (email, calendar), and "its file-based memory system". The UI path is Assistant → Identity → Memory (view and edit). Reset is under Settings → Data Controls → Reset Muse. Connector data is "part of your AI interactions, which we use to improve AI at Meta." — [Morphika guide](https://www.morphika.ai/guides/meta-muse-memory)
- **Product surfaces [3P, 2026-09-09]:** users can "inspect and edit Memory files". The "Goals tab tracks tasks and plans". "Side chats separate complex projects" next to one persistent main conversation. Muse can "respond to schedules and relevant events" and "decide whether new results warrant a notification", with user controls to "reduce, increase or disable that behavior". There is an activity log of actions and approved permissions. — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/)
- **Layered file memory, from hands-on testing [3P, 2026-09-14]:** Muse has "a persistent Linux virtual machine with a bash shell, a curated MEMORY.md file sitting alongside dated notes in a memory directory, semantic search across both, a real Chromium browser… and subagents". In the reviewer's chat, the agent described itself this way: "The top layer is a curated file I maintain myself: durable facts, preferences, commitments." "My memory is layered, not scored… When someone tells me something important, I'm instructed to write it down immediately, before I even reply." On compaction: "Compaction summarizes long conversations… the summary decides what survives, and I don't get a vote after the fact." Also "Background jobs continuously update memories, relationships and goals." The article is explicitly modelled on OpenClaw. — [Stark Insider, Meta Muse vs OpenClaw](https://www.starkinsider.com/2026/09/meta-muse-vs-openclaw-personal-ai-agent.html). Caution: these quotes are the agent describing itself, which is weak evidence about real internals.
- **OpenClaw parallel (for comparison) [Official OpenClaw docs]:** in OpenClaw, MEMORY.md is long-term memory loaded at session start. `memory/YYYY-MM-DD.md` daily notes are indexed for memory search "but not injected into the bootstrap prompt on every turn." — [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory) (search-snippet level). Muse's reported layout matches this. Whether Muse also injects MEMORY.md and retrieves the dated notes is **inferred, not confirmed**.
- **External memory via MCP [3P vendor docs]:** Hindsight documents Muse using it as a "custom connector" that "calls the memory tools itself" (`recall`, `retain`, `reflect`, `get_mental_model`). The note says "Muse runs in Meta's cloud and has no plugin host, so Hindsight can't hook into its prompts or transcripts." — [Hindsight integration page](https://hindsight.vectorize.io/sdks/integrations/meta-muse). So Muse supports user-added MCP connectors and exposes no prompt or transcript hooks.

### Inferences
- Muse is a closed, hosted version of the OpenClaw pattern that Jarvis already follows: a curated index or memory file, plus dated daily notes, plus search, a background process, and a user-editable memory. That is outside confirmation that Jarvis's markdown memory layout matches where a large vendor landed. Muse adds semantic search over the dated notes, a write-it-down-before-replying rule, a Goals surface, and side chats.
- The notification decision ("decide whether new results warrant a notification", tunable by the user) matches Jarvis's `heartbeat_respond(notify=...)` ack. Muse exposes the threshold as a user setting.
- Both vendors admit forgetting is imperfect ("may still remember what it learned"). They only remove explicit records, not anything derived from them. For a single-owner system, keeping derived state in plain inspectable files makes forgetting actually checkable.
- The compaction quote ("the summary decides what survives") is a lesson that carries over. Lossy summarization of a capped thread needs a write-durable-facts-first step, which Muse reportedly enforces by having the agent write memory before replying.

### Gaps
- No Meta engineering post, talk or paper on Muse memory was found. I could not determine what is injected per turn versus retrieved, the search method, or how background jobs consolidate memory (cadence, triggers, conflict handling).
- The "background jobs continuously update memories" claim comes from a comparison article and the agent's self-reports. It is not confirmed in Meta's help page as fetched.
- Sentinel's role in memory, if any, is undocumented. Real-world lessons and evals do not exist yet, about four weeks after launch.

## Lessons transferable to a single-owner proactive assistant (Jarvis)

### Takeaway
Both 2026 launches converge on the same shape Jarvis already has. A durable curated profile or memory file, a separate agent-written notes layer (not transcripts), background/idle work that writes notes and decides whether to notify, schedule/event/self-scheduled wakes, and per-surface context assembly. They differ mainly on **transparency**: Muse uses visible, editable files, while dots keeps opaque notes that can only be removed by deleting the dot. Neither has published evals, costs or post-mortems yet.

### Cited Findings
- Read-only background research with side effects gated to normal paths (dots) — [DataCamp](https://www.datacamp.com/blog/openai-dots); [SEJ](https://www.searchenginejournal.com/openai-dots-read-only-proactive-research/591565/)
- Self-scheduled, user-scheduled and event-driven wakes (dots) — [Flavio Copes](https://flaviocopes.com/openai-dots/); schedules plus events plus a tunable notification threshold (Muse) — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/)
- User-trust friction: dot memories cannot be viewed or edited, and learning outlives disconnected apps — [Flavio Copes](https://flaviocopes.com/openai-dots/); [DataCamp](https://www.datacamp.com/blog/openai-dots). Muse forgetting is best effort — [Meta Help](https://www.meta.com/help/artificial-intelligence/1047255454427887/)
- Cost: background work for dots draws on an unpublished allowance after month one — [DataCamp](https://www.datacamp.com/blog/openai-dots)
- Upstream background consolidation ("Dreaming") reportedly doubled factual recall on OpenAI's eval (41.5% to 82.8%) — [ResultSense](https://www.resultsense.com/news/2026-06-05-openai-chatgpt-dreaming-memory/)

### Inferences
- Candidate changes for Jarvis's redesign:
  - (a) Formalize a notes layer that is distinct from both chat history and USER.md.
  - (b) Make heartbeat ticks read-only unless they go through the confirmation or notify path.
  - (c) Add a "write durable facts before replying" rule to prevent loss when the 50-message thread is cut off.
  - (d) Consider a periodic Dreaming-style consolidation task that reviews chat history and updates curated memory, since that is the one consolidation mechanism with a published, if third-party-reported, recall gain.
  - (e) Keep memory human-readable and editable; both vendors' forgetting weak spots argue for it.
  - (f) Let foreground and background turns assemble different context slices, as dots does.

### Gaps
- No published cost figures, failure analyses, or user-trust studies exist for either product as of 2026-10-06.
